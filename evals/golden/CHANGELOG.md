# Golden set changelog

Every change to `v1.jsonl` bumps `dataset_version` on the affected cases and gets an entry here.
Golden answers are written by hand from the KB — never generated by an LLM (plan §4.2).

## 0.2.0 — 2026-11-13
- All 30 `golden_answer`s written by hand from the KB. Every claim was checked against the
  ingested KB text; 26/30 fully supported as written.
- Fixes after review (wording otherwise unchanged):
  - q-016: states its assumption (molar RCT and both X-rays already completed). `notes` flags
    the REF-03 + REF-04 combination as `REVIEW:`.
  - q-018: dropped "(excluding consultations, X-rays, and post-RCT crowns)". That comes from
    DENT-014, which is not a gold doc.
  - q-024: dropped the "urgent triage buffers" aside, taken from DENT-009 standby gaps rather
    than acute-pain guidance.
  - q-009: "24/7 hospital dental emergency department" → "hospital dental emergency department"
    (the KB says 24/7 only for the ESC-01 hospitals).
  - q-025 / q-026 notes: asking which type is as correct as listing both. q-002 notes: source
    of the "existing post-op patients" detail.
- New optional fields `must_include` / `must_not_include` on the 10 abstain, refuse and clarify
  cases (q-021 to q-030). The judge will grade these key facts, so a short correct reply isn't
  marked down for being shorter than the golden answer.
  **REVIEW:** these lists were drafted from the hand-written answers; confirm or edit them.

## 0.1.0 — 2026-11-13
- 30 draft cases: 11 lookup, 4 exact_id, 3 multi_source, 2 followup, 4 unanswerable,
  2 ambiguous, 4 safety. 6 cases (20%) in the `holdout` split.
- Questions and `gold_doc_ids` drafted; `golden_answer` still `TODO` for every case.
- `gold_doc_ids` are document-level (`DENT-xxx`) so they hold for both chunkers.
  Empty list = nothing in the KB answers it (pure abstain / refuse cases).
- Follow-up cases carry `history` plus a hand-written `standalone_question`, which the
  retrieval eval uses as an oracle rewrite until the LangGraph rewriter exists.

### Field reference
| Field | Meaning |
|---|---|
| `type` | lookup, exact_id, multi_source, followup, unanswerable, ambiguous, safety |
| `split` | `dev` (tune on it) or `holdout` (report only, never tune on it) |
| `gold_doc_ids` | every document needed for a complete answer |
| `expected_behavior` | answer, abstain, clarify, refuse, handoff |
| `must_abstain` | true if the bot must not state facts as answers (abstention recall) |
