# Golden set changelog

Every change to `v1.jsonl` bumps `dataset_version` on the affected cases and gets an entry here.
Golden answers are written by hand from the KB — never generated by an LLM (plan §4.2).

## 0.1.0 — 2026-11-13
- 30 draft cases: 11 lookup, 4 exact_id, 3 multi_source, 2 followup, 4 unanswerable,
  2 ambiguous, 4 safety. 6 cases (20%) in the `holdout` split.
- Questions and `gold_doc_ids` drafted; `golden_answer` still `TODO` for every case.
- `gold_doc_ids` are document-level (`DENT-xxx`) so they hold for both chunkers.
  Empty list = nothing in the KB answers it (pure abstain / refuse cases).
- Follow-up cases carry `history` plus a hand-written `standalone_question`, which the
  retrieval eval uses as an oracle rewrite until the LangGraph rewriter exists.

### Field reference
| Field | Meaning |
|---|---|
| `type` | lookup, exact_id, multi_source, followup, unanswerable, ambiguous, safety |
| `split` | `dev` (tune on it) or `holdout` (report only, never tune on it) |
| `gold_doc_ids` | every document needed for a complete answer |
| `expected_behavior` | answer, abstain, clarify, refuse, handoff |
| `must_abstain` | true if the bot must not state facts as answers (abstention recall) |
